# 内置工作流（开源版 0.1.28）

这 4 套模板来自维护者当前实际启用工作流的只读配置导出，不是新编造的示例图。导出未修改生产数据库、服务或源码，未启动任何 Colab runtime。**模板来自已有配置，不等于这次在新安装上重新做过真实 GPU 验收。**

## 目录

位置：`api/app/gpu/templates/builtin/`。`catalog.json` 是目录索引；每个 JSON 包含 `model` 元数据、`manifest`、`api_graph`、所需节点的 `object_info`。JSON 兼容现有工作流 bundle 导入格式，可供旧安装或其他副本手动导入；当前版本已自动注册的同 key/version 无需再导入，重复导入会触发版本唯一性保护。

| 文件 | 用途 | 版本 | 参数对应规格 |
|---|---|---|---|
| `krea2-moss-dual-t2i-1.0.0.json` | Krea 构图 + MOSS 精修 | 1.0.0 | T4 HighRAM |
| `moss-image-sft-t2i-1.0.0.json` | MOSS 单图 | 1.0.0 | T4 |
| `minimax-h3-i2v-1.1.0.json` | 首帧/可选尾帧，原生音频 | 1.1.0 | L4 |
| `minimax-h3-ref2v-1.4.0.json` | 最多 6 张参考图，原生音频 | 1.4.0 | L4 |

规格只是模板默认配置，不保证每个账户有对应资格，也不保证全部尺寸/时长不爆显存。15 秒等长视频参数没有在此次整理中做真实试跑。

## 新安装会发生什么

- 登录后读取模型/工作流时，内置目录自动补充为 4 个草稿。
- 3 个对应真实模型元数据自动注册，`enabled=false`。
- 不复制维护者的发布、reviewed、smoke、许可同意或硬件实测记录。
- 不下载权重，不请求 Google，不创建 CPU/GPU runtime。
- 同一用户重复请求幂等；已有同 key/version 的记录完全保留。
- 不覆盖现有默认指针、已发布工作流、用户改名或已审核模型。
- 不同用户分别注册，记录归属不共享。

草稿会出现在“工作流”页，但不能立即在“创作”页运行；只有完成当前安装自己的审查与真实验收并发布后，才会变为可运行版本。这是安全边界，不是导入失败。

## 如何启用

1. 配置自己的 Google OAuth、Drive 与预算费率。
2. 阅读并接受各模型、LoRA 和节点的独立许可。
3. 在工作流页校验草稿。
4. 按 `WORKFLOW_REVIEW.md` 完成模型和工作流管理员审查。
5. 自行明确授权最小真实冒烟；这是可能收费的操作。
6. 确认产物保存、哈希正确及 runtime 已删除。
7. 调用验收接口并发布所需工作流版本。

不会把维护者的成功记录当成你的授权，也不会为了“开箱即用”跳过审批。现有全局 `GPU_REAL_ENABLED=0` 默认值保持不变。

## H3 多参考图 1.4.0

保留五种模式：快速 4 步、快速 8 步 v1.1、4 步+精修、8 步 v1.1+精修、高质量 20 步。默认 `fast8`，VAE 默认二次元/CG 无缝版，可切官方原版；精修使用锁定提交的 3D 潜空间放大节点。固定提交、权重文件名、SHA-256、参数绑定与节点连接都随模板提供。

LoRA 精选目录仍由现有 `api/app/gpu/loras.py` 提供，本次未改写该目录，不包含维护者私传 LoRA 或 Drive 文件。
