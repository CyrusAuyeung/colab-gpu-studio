# v0.2.0 迁移与回退操作

本文件用于离线验证和发布审查，不构成生产部署授权。生产修改须另行安排。

## 升级前

1. 停止接受新任务，等待队列收尾。
2. 列出全部未删除实例、旧租约和未知资源；未知不等于已关机。
3. 使用当前版本的实例停止操作请求回收，待服务端确认远端不存在。
4. 对数据库、作品目录和部署配置做独立备份；配置与加密密钥仅保存在受限备份位置，不上传 GitHub。
5. 在备份副本上执行迁移、校验旧作品及任务数量和归属、执行离线回归。

SQLite 在线备份应使用 SQLite backup API 或停写后的完整复制，不能只复制正在写入的数据库主文件而遗漏 WAL。PostgreSQL 使用与服务端兼容版本的 `pg_dump`，并实际验证恢复。不要把密码放在命令行或日志。

## 新数据结构

账号与实例独立于 Job；旧 Google 用途凭据挂载到稳定的历史默认账号；旧 Lease 构造稳定实例外壳。明确已删除的旧资源保持已删除，其余无法确认的状态为 `unknown`，不能凭迁移推断远端已关闭。迁移不会调用 Google，也不会开机。

升级命令（针对隔离数据库副本验证后再用于授权环境）：

```bash
uv run alembic upgrade head
```

升级后启动同版本 API、worker、watchdog，先核对账号、任务、作品和实例归属，再开放任务准入。禁止只更新 API 而让旧版 watchdog 管理新实例。

## 回退

- 回退前停止准入，使用新版回收所有在线/保留/未知实例，并核实删除。仅取消 Job 不等于停止空闲保留实例。
- 若仍有 `unknown`、`cleanup_pending`、`quarantined` 或其他未确认删除状态，保留新版 watchdog 与管理能力，暂停回退；不得让旧版遗失资源管理。
- 降级脚本应拒绝存在活动实例的数据库。不要手工把状态改成 `deleted` 来绕过检查。
- 确认清空资源后，可以回退应用代码并保留增量表，或恢复升级前经过验证的独立备份；恢复会丢失备份之后的新任务记录，需先导出审计证据。
- 旧版不认识实例级保留和账号路由，所以不能继续接管未清理的 v0.2.0 实例。

真实 Google 授权、GPU 保留与回收、Comfy 常驻及实际 CU 需单独授权短会话验收；离线测试通过不能替代这些结果。
